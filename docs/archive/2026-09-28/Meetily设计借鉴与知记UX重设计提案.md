# Meetily 设计借鉴与知记 UX 重设计提案

> 基于 Meetily 真实截图（home/summary/editor/settings/audio）与知记 v1.2.15 代码逐帧对照。

---

## 一、Meetily 做对了什么（截图级拆解）

### 1. 首页即录音屏：零 friction 开始
- 打开应用就是一块大白板，中心是转写流。
- 左侧边栏最显眼的是**大红录音按钮**；底部悬浮着暂停/停止/波形控件。
- 没有"新建会议→进详情→再点录音"的断点。

### 2. 内容优先，UI 靠边
- 转写占 60% 以上可视区域，时间戳极淡、`[00:00]` 小字。
- 顶部只有 4 个工具按钮（Copy / Model / Devices / Language），不常驻 AI/转写/纪要按钮。
- 录音时画面"就是文字在滚动"，没有多层卡片/标题/提示。

### 3. 摘要页是"转写 + 纪要"双栏
- 左：原文；右：AI 产出。
- 右栏顶部一行操作：Generate Note / AI Model / Template / Save / Copy。
- **产出结构清晰**：Summary → Key Decisions → Action Items（表格：Owner / Task / Due / Reference Transcript Segment）。
- 左下角常驻"Add context for AI summary..."输入框，始终可见，不强求先填。

### 4. 设置用 Tab 分块
- General / Recordings / Transcription / Summary 四标签，信息分层，不像长表单。
- 音频设备用**弹窗**（Audio Device Settings），不离开主设置页。

### 5. 状态语言极简
- 录音中：`Recording • 02:44` + 红点。
- 收集中：`Listening...` + 蓝点。
- 没有"正在进行中..."这类模糊描述。

## 二、知记当前操作链的痛点

当前完成一次会议的完整链路（v1.2.15）：

```
首页 → 点击"开始会议" → 进入会议详情
  → 点"录音并转写" → 录音 → 点"结束录音并转写"
  → 自动转写中…
  → （可能需要点"区分说话人"）
  → 滚动到下方 AiWorkflow 或点纪要栏右上角"重新生成"
  → 生成智能纪要
```

### 痛点 1：没有"开始录音"的一等公民入口
- 首页"开始会议"只是创建会议，不会立刻录音。
- 用户需要先进详情、再点录音，两步才能开始。

### 痛点 2：三栏同时铺开，信息过载
- 左：我的笔记；中：原文转写；右：智能纪要。
- 三块都带标题、hint、计数徽章、按钮，眼睛不知道先看哪。
- "我的笔记"长期占 1/3 宽度，但多数会议后回看时优先读转写/纪要。

### 痛点 3：会前背景不够显性
- 当前是可折叠条，默认空状态展开、有内容收起。
- 用户反馈"纪要不准"时，才意识到没填 context。

### 痛点 4：AI 操作按钮分散
- 顶部有 AI 重命名；录音条有转写/导入；底部 AiWorkflow 有一排按钮；纪要栏有重新生成。
- 同样能力（转写/纪要）出现多次，但位置不同。

### 痛点 5：决策待办仍是文本
- `decisions` 是 textarea，LLM 输出的待办无法结构化展示。
- Meetily 的 Action Items 表格一眼就能看 Owner/Due/Reference。

### 痛点 6：设置页平铺过长
- 当前是一整页滚动，模型下载、AI 设置、转写设置、关于混排。

## 三、重设计方向（不推翻已有视觉语言）

保留：微信绿 #07C160、窄图标边栏、无头像、无重编辑器、纯本地优先。

改变：**从"管理会议"转向"聚焦当前会议"**。

### 方案 A：首页增加"直接录音"入口（P0）
- 首页保留"最近会议"，但"开始会议"按钮改为两态：
  - 主按钮：`开始新会议`（创建 + 立即录音）
  - 次按钮：`导入录音` / `查看全部`
- 或者首页即"录音仪表盘"：顶部大按钮开始录音，下面是最近会议。

### 方案 B：会议详情改为"转写 + 纪要"双栏（P0）
- **左栏 60%**：原文转写（默认展开说话人时间线）。
- **右栏 40%**：智能纪要 + 决策待办。
- **"我的笔记"**：收进左下角可展开抽屉，或顶部 Tab 切换，默认不占主空间。
- **会前背景**：放到右栏纪要的上方或左栏底部，作为常驻一行输入框（像 Meetily 的 context input）。

### 方案 C：AI 操作统一为右栏工具条（P1）
- 右栏顶部固定工具条：`生成/重新生成纪要` | `纪要服务商` | `模板`（远期） | `复制`。
- 底部 AiWorkflow 精简或隐藏，只在缺配置时提示。

### 方案 D：结构化决策待办（P1）
- LLM 输出 markdown 表格或结构化 JSON，前端渲染成 Action Items 表格。
-  schema 增加 `tasks` 与会议关联（已有），但纪要栏里把待办以表格呈现，并支持勾选完成。

### 方案 E：设置页 Tab 化（P1）
- 通用 / 录音与转写 / 纪要 / 关于更新 四标签。
- 音频设备、模型下载用弹窗卡片。

### 方案 F：转写视图状态简化（P2）
- 把 `【说话人1】` 标签改成色块/圆点 + 名字，像 Meetily 的说话人区分一样轻量。
- 时间戳默认折叠，hover/点击才显示。

## 四、优先落地顺序

| 优先级 | 改动 | 预估影响 | 复杂度 |
|---|---|---|---|
| P0 | 首页"一键开始录音"（创建即录音） | 最大痛点，减法最多 | 中 |
| P0 | 会议详情改为 2 栏；笔记收抽屉 | 视觉降噪 50% | 中 |
| P1 | 会前背景常驻为底部/顶部输入框 | 提升纪要质量感知 | 低 |
| P1 | 右栏统一 AI 工具条 | 减少操作选择疲劳 | 低 |
| P1 | 设置页 Tab 化 | 降低设置认知负担 | 低 |
| P2 | 结构化决策待办表格 | 输出专业化 | 中 |
| P2 | 说话人标签轻量化 | 转写可读性提升 | 中 |

## 五、刻意不抄 Meetily 的部分

- **不迁移 shadcn/Tailwind/Next.js**：等于重写前端，违反"少维护"。
- **不用 BlockNote 编辑器**：与"不硬支持 md/html、纯 textarea"的既定决策冲突。
- **不做实时滚动波形**：可先保留当前录音条，后续再补。
- **不做首页就是录音屏**：知记已有首页/会议/待办/设置导航，不推翻，只在首页增强 CTA。

---

## 六、下一步建议

如果接受方案 A+B 作为下一个大版本，我可以：
1. 先做首页"一键开始录音"（最小改动，最大收益）。
2. 再把会议详情从 3 栏压缩为 2 栏 + 笔记抽屉，同步调整 CSS 响应式。
3. 顺带把会前背景做成常驻输入框。

这样一次改动就能把"操作流"理顺，后面的 P1/P2 自然叠加上去。
