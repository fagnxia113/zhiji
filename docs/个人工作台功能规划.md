# 知记个人工作台：产品与实施规划

更新日期：2026-10-11。依据用户最新澄清：按项目组织具体工作，同一项目可以跨多个主题；重点不是父子层级。结合大量会议与协调事项、本地 Word / PDF / PPT / 录音资料、材料撰写、包含日常事务的动态周报，以及 AI 调用进展和资料。本文是唯一现行规划，直接更新原文，不另建平行提案。

状态：第一阶段已开始实施，新增代码与验证边界见文末。后续阶段仍是规划；源码存在不等于已随正式安装包发布。

## 1. 产品目标与取舍

核心价值：**同一份资料和进展只整理一次，之后能找回来继续工作，并直接用于周报和 AI 写材料。** 让用户进入一项工作时，能直接找到背景、资料、当前进展与下一步；平时留下的记录能支撑周报，AI 能引用同一套资料协助写材料与准备 PPT。

核心流程：**收集资料 → 关联项目 / 活动 → 推进工作并记下进展 → 用同一依据形成周报或写作草稿 → 确认产出并继续跟进。** 项目、主题和时间是同一批工作的查看维度，不分别维护三套资料库。2026-10-11 的具体组织、动态周报和写作设计见第 10 节；本轮优先级以第 9.4 节为准。

- 以本地文件为第一接入对象，保留 Word、PowerPoint 等现有编辑习惯。第一版不自建 Office 编辑器，不强制搬动整个文件库。
- 项目是长期工作的入口；活动记录具体过程；资料可被多处引用；工作进展记录实际发生的变化；任务表示下一步行动。
- 时间是查看上述对象的维度，不再额外维护一套按周复制文件的目录。
- 周报是日常工作记录的输出，必须在首个功能闭环中交付；不能等所有资料功能完成后再补。
- 先改善真实项目的完整工作过程，再按测量结果优化性能；暂缓跨端同步、多人协作、复杂知识图谱和内置 PPT 排版系统。

统一设计约束：前端页面、导航、表单、搜索、AI 和数据能力都服务同一条核心流程。每项改动须说明帮助用户收集什么、在哪项工作中复用、减少哪次查找或重复输入；只有功能名称而没有具体工作场景的提案暂不开发。技术拆分不能变成用户需要理解的更多入口。

“只整理一次”指资料身份、关联和已确认事实可重复使用，允许后续补充与更正。用户忙的时候也能开始：收下一份资料或一句话即可，不要求先建项目、活动、任务，再逐层填写。项目承载持续工作；未归类和一次性工作仍能搜索、记录及纳入周报。

## 3. 信息组织规则

| 对象 | 必要信息 | 关联规则 |
| --- | --- | --- |
| 项目 | 名称、目标、多个主题、当前阶段、主要时间节点、归档状态 | 汇集活动、资料、任务和进展；主题与项目为多对多关系，归档不删除内容 |
| 主题 | 名称、相关项目、相关日常事务与通用资料 | 与项目为多对多关系；按主题聚合不复制项目或材料 |
| 活动 | 类型、发生时间、相关项目 | 会议有一个可选的所属项目，也可独立保留；通用活动保留跨项目引用。会议的主项目与已有活动共享关系分开 |
| 资料 | 稳定 ID、标题、文件类型、位置、版本、解析状态 | 同一份资料可关联多个项目 / 活动；用途为会前参考、过程记录、产出等 |
| 工作进展 | 实际发生日期、内容、结果 / 阻碍、关联对象、记录时间 | 一次实质进展单独记录；更正保留历史，不能用改文件时间代替进展 |
| 任务 | 内容、当前状态、来源、负责人、截止日、可选计划日期 | 一个任务可跨周推进；完成是进展事件之一；修改描述不等于完成工作 |
| 周报 | 周期、范围、正文、版本、材料快照、模板版本 | 保留当次使用的来源版本；后续文件变化不能悄悄改写已保存周报 |

边界约定：

- 活动发生时间、资料修改时间、实际进展日期、记录时间和截止日期分开使用。
- 项目可关联一个本机资料文件夹，作为打开与选择文件的入口；其他目录的资料仍可关联到同一项目。关联文件夹不自动扫描、复制或移动内容，数据库备份保存路径与关系，不包含原文件。
- 会议页直接选择可选所属项目并进入项目，项目活动页可打开同一场会议；直接关联的会议与已有会议活动合并展示。更换主项目后，由主项目派生的活动和资料范围随之变化，原有跨项目活动引用保留。
- 允许先收集、后归类；从项目或活动内添加资料时自动继承关系。
- 共享资料不靠复制实现；重复导入时提示复用。文件同名不代表相同，内容相同也不自动强制合并业务记录。
- 取消关联不删除原资料。工作台内的原文件删除与清理索引是不同操作，第一版默认只解除关联。
- 同一进展关联多个项目时，汇总整份周报须按稳定事件 ID 去重；保留相关项目引用。
- 项目共用的参考资料不是每周新增成果。只有实际使用产生的新进展，才进入本周成果候选。

## 4. 页面与日常流程

当前导航仍为工作台、工作记录、行动待办、周报、项目和会议资料；设置位于底部，全局搜索常驻。下表是围绕核心价值收敛后的目标设计，尚未替换现有导航；当前已实现范围以第 8 节为准。

| 位置 | 用户在这里完成什么 | 界面与功能的统一职责 |
| --- | --- | --- |
| 工作台：收集与续接 | 记下一句话、收下材料、继续上次工作 | 首屏突出当前可继续的工作及轻量收集；未归类内容允许留待整理。跨项目的会议、待办和记录作为汇总视图可访问；不要求先建立完整项目结构才能开始 |
| 项目：日常工作的中心 | 找背景与材料、处理活动、推进工作、保存进展 | 沿用「概览 / 资料 / 活动 / 进展」标签；概览展示当前行动与最近进展。活动详情汇集准备材料、记录、结论和后续行动；打开会议、资料或进展编辑时保留当前项目与返回位置 |
| 周报：复用日常成果 | 选周期、核对事实、编辑确认、保存输出 | 自动汇集已有事实，显示项目归属和可回到原文的依据；只需核对、勾选和修改表达。新版本与旧版清楚区分，事实不要求重新录入 |
| 全局搜索：跨范围找回内容 | 从关键词或问题找到资料及上下文 | 显示内容、归属和定位，进入具体对象；搜索与返回保留正在编辑的草稿。正文不可读、无匹配及读取失败分别说明 |
| 写作：形成可交付材料 | 根据选定项目 / 主题的最新进展和资料写汇报、简报或 PPT 提纲 | 可从当前项目直接进入；显示写作用途、资料范围、截止时点和实际读取的来源。草稿与版本保存回相关项目 / 主题，界面与 MCP 使用同一资料和读取规则；正文解析与写作工作区仍待开发 |

目标主导航为“工作台 / 项目 / 周报 / 写作”。主题放在项目浏览器的“按项目 / 按主题”切换中，不再增加同级主题模块。会议、任务和记录保留完整能力及跨项目汇总入口，日常流程优先从当前项目直接操作。设置保持辅助位置。导航调整须与上下文入口一起交付，不能仅移除原入口而让原有资料难以访问。

项目概览要先回答“上次做到哪里、相关材料是什么、下一步是什么”。活动数量、文件数量与任务截止日期是辅助信息。具体行动可直接进入处理，进展与关联材料能互相定位；同一条工作记录可按时间或项目查看，切换视角不重新录入。用户只记得关键词时可直接从搜索开始，不强制先回忆项目名称。

示例：在“专题调研”项目添加一次评审活动，关联议程 PDF 和汇报 PPT；录音形成纪要及修改任务；用户完成报告修改，记录“已提交初稿，等待反馈”并关联该版 Word。周报按项目汇总这条进展，同时引用评审和报告，不把参与评审、完成修改、提交初稿重复当成三个独立成果。

## 5. 分阶段实施

### 第一阶段：项目—活动—本地资料—周报的最小可用流程

具体交付：

1. 增加项目详情页和通用活动登记，现有会议可关联到活动，保留原会议 ID、录音和命令。
2. 支持选择或拖入本地文件，登记路径并关联项目 / 活动；点击用原程序打开。允许同一资料复用，不移动原文件。此阶段只搜索文件元信息，不宣称能搜索尚未解析的正文。
3. 扩展现有工作记录，使进展能关联活动、任务和资料版本；引入追加式进展事件及更正记录。任务完成产生事件时使用稳定键，防止重试造成重复。
4. 周报沿用现有生成、编辑、档案和快照能力，增加进展 / 产出材料、人工勾选、项目分组和“本周进展—成果—问题—下周计划”模板。下周计划需用户选择，不能把全部未完成事项自动视作承诺。
5. 沿用本地 API 的项目上下文与周报材料工具，让 AI 能读取已授权的新增进展和文件元信息；未解析内容明确返回状态。

验收：一个真实项目、至少三次活动、一个共享参考文件、跨两周推进的任务、一个 Word / PPT 产出。重启后关系不丢；不复制共享文件；周报只把实际发生的工作列为成果；同一事件重试不重复；旧会议、周报、备份仍可读取。

这一阶段不等待文件全文解析全部完成；先证明“资料找得到、工作接得上、周报写得出”。

### 第二阶段：文件正文可查，AI 回答有依据

- 优先解析 DOCX、PPTX、文本型 PDF、TXT / Markdown；复用现有音频转写。旧 DOC / PPT、扫描 PDF 先显示需要转换 / OCR，随后按真实占比补齐。图表、嵌入对象及图片不能冒充已完整理解。
- 后台解析任务可重试、取消，并按文件版本更新索引；失败不影响原文件打开。第一版使用手动刷新或受控扫描，随后再考虑目录监听。
- 统一查询项目、活动、记录、任务、周报和资料内容；列表分页和详情读取配套实施，资料汇总不受列表分页限制。
- 结果携带稳定资料 ID、版本与定位信息：PDF 页码、PPT 页号、Word 章节 / 段落、录音时间点。Word 页码随排版变化，不作虚假的精确定位承诺。
- 增强现有 MCP / API：按范围搜索 → 读取选定片段 → 获取项目或活动上下文；限制一次返回量并明确截断，允许继续读取。纯云端客户端不能直接连接本机 localhost。

验收：在示例项目中，能从问题找到原始资料及对应位置；未解析 / 失联材料有提示；多项目共享与访问范围一致；范围检查同时覆盖搜索和按 ID 读取，不能通过猜测 ID 读取范围外资料。

### 第三阶段：辅助产出与持续回顾

- AI 基于选定资料生成材料草稿、PPT 提纲或周报，显示依据与待补信息，保存为新版本并关联回项目。
- 正式提交或评审使用的文件可保存不可变快照；不自动覆盖原文件。直接生成可编辑 Word / PPT 文件作为独立交付项，不能把提纲生成等同于已完成文件制作。
- 周报补固定模板、上周计划对照和未完成原因；月报 / 项目汇报复用同一批进展事件，避免逐层摘要造成事实丢失。
- 增加今日计划、继续上次工作和个人工作材料集合；默认减少填写，不要求用户维护复杂关系网。

验收：从一项具体写作任务进入，找到依据、生成草稿、保存产出、纳入周报都可连贯完成；同一周报的历史版本与来源不受后续编辑影响。

## 6. 技术实施边界

- 沿用 Tauri / React / Rust / SQLite 和现有 workbench 服务。无需因关系增加就引入图数据库，也不先把全部代码重写。
- 建议增量增加 activities、resources、resource_versions、明确的关联表，以及 work_events / event_sources。具体命名在实现时统一；不要同时保留两套互相独立的项目关系真值。
- 会议先通过唯一 meeting_id 关联活动，逐步迁移 UI；旧会议仍可独立使用。现有单项目关联迁移成主要关系；新关系允许共享。旧的工作记录迁移为已知记录，不捏造早期状态变化或完成时间。
- 新表与版本迁移同步覆盖备份、恢复、导出、外键和清理。新增资料版本需要区分“引用原文件”和“已保存快照”：前者只保证能重新定位，后者才可保证原始字节可追溯。
- 引用模式的数据库备份不含外部文件。托管副本 / 版本快照交付时，必须一并提供包含文件、清单、校验值的完整备份与恢复流程。
- 周报从进展事件汇集事实；AI 负责组织表达，不把打开文件、参加会议或编辑文件自动判定为完成成果。识别重复材料和归属时给建议，不悄悄改变关联。
- 每项功能同时交付界面、数据迁移、导出恢复与测试；测试使用隔离数据，原生验收见 [产品验收](产品验收.md)。

## 7. 工程支撑与暂缓事项

以下工作继续推进，但不再替代上述产品主线：

- 发布检查：三处原生版本与 tag 一致，更新工作流中固定的 releaseBody；流程见 [发布手册](../RELEASE.md)。
- AI 稳定性：当前修复分支的 chat_completion 已限制为最多三次尝试、单次至多 240 秒、总预算 360 秒，超时不自动重试；长会议已支持最多两段并行及成功片段短期复用。后续写作仍需整项任务取消、可见进度和分段续作；不能把候选分支能力当成已安装版本能力。
- 性能：用 100 / 1,000 / 10,000 条合成资料测量，再决定分页与索引方案。不可单纯加 LIMIT 使统计、周报或搜索静默漏数据。
- 模块拆分：随活动、资料、进展、报告等职责抽出模块。当前未接入的 search_index.rs 不能作为已具备全文索引的证据；清理历史源码前检查构建与资源引用。
- 暂缓：外部办公平台全接入、多端同步、多人权限、内置 Office 编辑器、关系图可视化、任意拖拽布局。

### 数据、草稿与代码职责

- 活动、文件可跨项目引用；原文件不搬动、不删除。SQLite 保留工作记录更正和任务状态事件，进展来源与已保存周报保留当时元信息。现有 MCP 与界面共用服务和项目授权范围。
- [共享工作台状态](../apps/desktop/src/zhiji/workbench/store.ts) 在同一窗口只读取一份初始快照并建立一次订阅，页面与全局搜索共同使用。连续刷新合并且顺序执行，旧读取结果不覆盖新请求；失败保留上一次可读数据。
- 项目界面与 [工作区操作](../apps/desktop/src/zhiji/components/projects/useProjectWorkspace.ts)、[数据生命周期](../apps/desktop/src/zhiji/components/projects/useProjectData.ts) 分开。保存和重新读取更新项目资料及全局工作记录两份视图，写入完成但刷新失败时阻止重复提交；外部接入的更新不覆盖编辑草稿。
- 草稿按字段校验缓存，非法类型、日期或枚举安全回退，有效正文保留。项目目标、活动和进展草稿记住来源；浏览资料、新增活动或切换专注模式不静默改变已有草稿。空白新记录使用当天日期，主动选择的历史日期与非空草稿日期保留。
- 缓存是本机临时状态，不属于数据库备份；点击保存后才成为正式记录。无效的折叠日期会展开提示。初次读取失败禁止保存；打开文件、取消文件选择不额外刷新目录；跨项目复用目录按需读取。
- 周报可选择材料并保存档案，区分活动登记、文件元信息、个人进展及实际完成事实。同一范围刷新保留勾选和展开状态；切换日期或项目重新选取材料；已保存版本仍展示其原范围，未保存正文受切换保护。文件登记不能当作已读取正文或已完成产出。

### 9.2 对现有布局的修正

当前前端采用自适应工作区，已接入范围见第 8 节。所有后续前端改动须满足第 4 节的页面职责和以下规则，不能按单个模块各自增加入口：

- 全局导航位置稳定，目标主要层级为工作台、项目、周报和写作；会议、待办和记录的汇总入口辅助跨项目查找。项目列表只有一份，主题、收藏和最近作为视图或筛选；宽窗列表与内容并排，窄窗集中显示当前内容。当前六项导航的收敛及独立写作工作区仍待实施。
- 项目内标签为「概览 / 资料 / 活动 / 进展」；默认页面突出本页主要操作，设置及低频表单按需展开。
- 从当前项目、活动或资料发起的操作继承上下文，明确显示归属；用户不必重复选择项目或重新添加已关联资料。同一录入、选材和引用操作复用一致的交互规则。
- 主操作随当前工作确定：开始时收集，进入项目后找材料或记进展，打开周报后核对与保存。首页不为每种能力平铺功能卡片；录音作为活动中的直接操作，保持快捷可达。
- 资料标签先显示查找与文件列表，常用打开/记录操作在详情上方，维护操作在下方。正文未解析时只显示元信息，并明确 AI 尚不能读取正文。
- 记录中的项目名称直接关联到对应项目；页面切换恢复筛选、查看位置和草稿。缩放只改变呈现方式，不改变项目或来源。列表方向键移动焦点，Enter 确认。
- AI / 来源 / 属性辅助区域仍待实现，按需打开且一次聚焦一项；断点按实际可用空间确定。保留原生 Windows 窗框和常规键盘操作。

### 9.3 功能怎样减少整理负担

1. **收集**：先记一句话或登记文件，允许暂未归类；在项目或活动中添加时继承关系，保持明显的归属提示。自动建议可以降低操作量，但不静默改变关系。
2. **续接**：工作台优先显示继续工作入口，打开后恢复项目及资料位置；独立今日计划按后续候选处理。最近打开的文件作为线索，不自动成为今日重点或本周成果。
3. **查找**：搜索可选择当前项目或全部资料，显示文件名、项目、日期、命中片段、版本和解析状态；准确名称与关键词检索始终可用。没有结果时区分“没有匹配”与“材料尚未解析”。
4. **产出**：提供“依据这些材料写汇报 / 准备会议 / 整理 PPT 提纲”等上下文操作。显示实际读取的资料、缺失内容与可定位引用，生成草稿保存回项目；提纲与可编辑 PPT 文件是不同交付状态。
5. **回顾**：完成一次提交或沟通时可留下一句话进展；周报从实际事件汇集，并提示本周材料缺口、等待反馈和上周计划变化。AI 生成、文件打开和文件修改不直接算作成果。

### 9.4 实施顺序与验证

v2.1.3 已交付项目标签、自适应布局、导航与草稿续接，以及项目、记录、会议、待办搜索。依据 2026-10-11 的使用场景，按以下顺序收敛功能；会后录音改造已通过候选构建，项目与多主题本轮已接入、候选验证中，其余新增能力为待开发。第 5 节的阶段划分继续说明各能力的交付边界。

2026-10-09 核对的具体断点：[项目资料](../apps/desktop/src/zhiji/components/projects/ProjectResources.tsx) 只能按文件名与路径查找，正文不可读；[项目概览](../apps/desktop/src/zhiji/components/projects/ProjectOverview.tsx) 的行动主要展示名称和来源会议，仍需切页处理；[首页](../apps/desktop/src/zhiji/components/WorkbenchHome.tsx) 主要按到期日排列行动。下一轮围绕同一组工作样本补齐这些断点，不以再次调整卡片或导航数量作为核心交付。

| 顺序 | 范围与交付边界 | 验收目标（待验证） |
| --- | --- | --- |
| 先做减法：会议会后处理 | 用户已确认保留“开始录音”，去掉边录边出字幕、实时校正、启动预热及相关设置；保留音频、会后转写、角色区分、回听校对与纪要。提交 cb5e859 已通过 [Windows 候选构建](https://github.com/fagnxia113/zhiji/actions/runs/38117636375)，尚未正式发布或更新本机安装 | 浏览器模拟音频已验证无模型录音、分段保存、笔记提交与会后转写顺序；Windows 编译、26 项原生测试与窗口检查通过。真实麦克风 / 系统声音及完整会议模型的候选端到端体验仍须按产品验收核对，不能以模拟结果替代 |
| 第一优先：项目与跨项目主题 | 本轮接入多主题选择、创建与改名、主题概览、按主题查询 / 周报、来源去重与备份。项目层级不列为本轮范围 | 同一项目在“出海”和“数据中心”视图均可找到且数据只存一份；解除关联保留原资料；主题不会扩大 AI 的项目授权 |
| 第二优先：动态周报复用事实 | 主题范围与全量日常事务已接入；材料持续更新，草稿增量确认仍待开发 | 项目进展与日常协调都进入本周候选；同一来源只出现一次；新增记录不覆盖用户编辑的正文；已保存周报保留主题名称与来源快照 |
| 第三优先：资料读取与 AI 写作闭环 | 在一组明确格式上先贯通正文解析、来源定位和范围读取，再提供按项目 / 主题写汇报的入口；优先 DOCX、PPTX、文本 PDF、TXT / Markdown，界面与 MCP 共用服务 | AI 使用实际读取的最新已确认进展和指定资料版本；输出可引用原文、提示缺口、保存草稿并返回项目；解析失败不阻碍原文件打开；生成草稿不冒充已交付成果 |

实施按完整流程逐步交付：用少量明确支持的材料完成“收集 → 搜索正文 → 查看出处 → 关联项目并记进展 → 周报复用 → AI 按范围读取”。同一批资料贯穿前端、数据库和 MCP 验收，再扩展格式及规模；每次增加解析能力都同时提供可用的搜索、来源定位和读取状态。当前录音、纪要、原文件打开等可用能力继续接入该流程。

整体评价用真实工作流程：登记一场会议及其材料，推进相关项目，恢复中断的材料撰写，再形成周报。记录寻找资料时间、为归类填写的字段、切换后丢失的位置、周报需要修正的事实数量。正式确定性能阈值和省时目标前先建立基线，不以截图更漂亮或功能数增加作为完成标准。

### 9.5 核心范围与取舍

- **项目组织工作，时间帮助回顾**：延续“概览 / 资料 / 活动 / 进展”标签。项目、活动和时间都是同一批资料的查看方式，不让用户重复建目录或录入同一事实。
- **默认少填写**：记录只要求正文，从项目或活动进入时继承关联；保存后成为可复用的事实。来源、日期和状态可核对、更正，不强制每条记录填写完整关系。
- **系统能确认的事实不让用户重抄**：已保存的任务完成事件和进展沿用现有记录，用户只补充缺失的结果；材料在会议、任务和周报出现时引用同一依据。文件被打开、被修改或被 AI 总结不自动成为工作成果。AI 推断的归属和成果需要核对，不能为了“自动化”写成确定事实。
- **个人周报表达个人参与**：会议中他人的行动和团队成果保持负责人及来源，归属不明时使用中性表述或提示核对；参与讨论、提交初稿、确认验收分别表达。现有周报已有相关提示与模型约束，验收还须覆盖多人会议、同一成果多处出现及完成后重新打开等样本。
- **AI 使用同一资料库**：先实现带来源的读取与检索，再让项目内问答、材料草稿和周报共用。AI 的价值以能否找到依据、减少重新整理来判断，回答引用实际读取的版本和片段。
- **可靠性随核心流程交付**：草稿保留、失败重试、关联更正、避免重复、历史快照及范围检查是核心功能的验收条件；文件正文索引与完整原文件备份分别说明。
- **后续候选暂不占本轮范围**：独立今日计划、跟进提醒、多状态任务流程、完整活动日程、文件夹自动监听、上周计划对照，以及 Word / PPT 模板导出。它们可在核心流程验证后按实际使用问题选择，不同时展开。

核心验收场景：同一项目有三次活动及 Word、PDF、PPT 材料。用户按一个问题找到原文；AI 引用选中的材料协助整理汇报；用户补充“已提交初稿，等待意见”并关联产出；周末按项目生成周报，该次提交只列一次并可返回依据。跨项目共享一份材料时不复制，重新打开后关联和已保存内容仍在。

同时用两个反例检查操作负担：没有项目的临时资料也能先收集并找回；忙了一周只留下会议记录、材料和少量进展时，周报优先复用已知事实，只提示具体缺口，不要求用户再录入完整工作日志。正文搜索、归属继承、自动复用和个人贡献判断尚未完成的部分，均明确列为待实现或待验证。

评价只看三件事：找回资料需要多久、同一事实需要录入几次、形成可用周报需要补充和修正多少内容。先用真实样本记录基线，再判断新增功能是否降低这些成本。新功能必须说明改善其中哪一项，否则放入后续候选。

## 10. 项目、主题、动态周报和写作如何串联

本节依据 2026-10-11 的最新澄清，项目与主题为两种查看方式，同一项目可跨多个主题。主题关联、概览、周报及 MCP 范围已通过 [Windows 候选构建](https://github.com/fagnxia113/zhiji/actions/runs/38119371640)。本轮继续接入会议的可选所属项目、双向导航和项目本机文件夹；新增部分仍须验证候选。动态周报增量合入、文件正文读取和独立写作工作区仍为目标设计。项目父子层级不列为本轮核心。

### 10.1 同一事实，多种查看方式

项目回答“这件工作怎么推进”；主题回答“这一类工作总体怎样”；时间回答“这一周实际发生了什么”。同一会议、文件或进展使用稳定标识，在不同视图引用，不因跨主题复制。

- 用户先按实际工作建立项目，不必先设计层级。主题独立于项目，可同时覆盖多个项目，一个项目也可进入多个主题。
- 项目与主题为多对多关系，例如“海外数据中心合作”同时属于“出海”和“数据中心”。主题页汇集相关项目、最新进展、待协调事项和通用资料。
- 日常事务允许不关联项目，全量周报包含这些内容；主题范围只包含关联项目，界面明确提示。日常事务和政策、行业报告等通用资料直接关联主题作为后续候选，不要求用户创建“杂项项目”。
- 项目内录入带上项目关系，本轮主题由项目关联得到。日期默认当天，忙时只记一句话，不要求先填全分类字段；记录独立主题仍待开发。
- 跨主题和多项目会议汇总按事实 ID 去重。同一来源只出现一次；相同事项的不同进展仍由周报编辑合并表达。已保存周报保留当时的主题名称及来源快照。

### 10.2 项目详情先回答四个问题

概览先展示“目前做到哪里 / 有什么阻碍 / 等谁协调 / 下一步做什么”，并显示最新确认时间与依据。详情沿用“概览 / 资料 / 活动 / 进展”的顺序，可将“活动”向用户表述为“会议与协调”。主题概览显示最近记录的进展，不推断项目已完成；重复出现在近期进展中的等待事项不再在协调区重复展示。

| 标签 | 内容及常用操作 |
| --- | --- |
| 概览 | 目标、当前阶段、最近确认的进展、待协调事项、下一步 |
| 资料 | 参考资料与工作产出，按用途和版本查看；用原应用打开，同一资料可跨项目 / 主题复用 |
| 会议与协调 | 会议录音、转写、角色、纪要及行动；协调事项显示对象、当前结果、等待方与下次跟进，简单沟通允许只记一句结果 |
| 进展 | 实际推进时间线；区分讨论、提交、等待反馈、确认完成；可回到相关会议和产出资料 |

“项目最新进展”来自已确认的变化及其历史，不取最新文件修改时间，也不由最后一场会议自动推定。会议说“拟提交”、任务安排“下周提交”和实际“已提交待反馈”分别保存，出现冲突时提示核对；AI 不自行编造完成率或覆盖项目状态。

### 10.3 动态周报：材料持续积累，正文由用户确认

默认个人周报范围为本周全部工作，包含项目进展和无项目的日常事务。可切换按项目或按主题组织，不要求重复录入；缩小到某主题时明确提示日常事务是否仍在范围内。

1. 平时的进展、协调结果、已确认的个人行动和交付记录持续进入本周材料候选；开会、打开文件、生成 AI 草稿不直接算作成果。
2. 周报页面展示当前候选与已使用依据，默认组织为“重点项目 / 日常事务 / 问题与待协调 / 下周计划”。下周计划沿用用户确认的承诺，不自动收下所有未完成待办。
3. 草稿生成后，新增或更正记录只提示“新增 N 条 / 更正 N 条”；用户查看事实差异后选择合入，保留已经手工编辑的正文。材料池更新不等于自动重写整篇周报，也不对每次记录自动调用 AI。
4. 定稿保存正文与引用来源版本；新资料、项目主题变化或后来完成的事项不改写旧版。跨周推进的事项按当周实际变化描述，不每周重复宣称完成。

### 10.4 写作：先确定范围和时点，再生成正文

入口既可在项目 / 主题中点击“写汇报”，也可在统一写作工作区继续旧草稿。用户主要提供用途、面向谁、篇幅；进入时继承当前项目 / 主题和已有资料，按需调整，不重新搭建资料库。

生成前显示两类依据：“截至某日的最新已确认进展”和“本次选用的参考资料 / 版本”。历史背景、目前事实、下步计划分开；文件缺失、未解析、内容冲突或指标缺乏依据时列出具体缺口，不把文件名当正文。正文中的陈述可返回工作记录、会议时间点、PDF 页、PPT 页或 Word 段落。

写作工作区主要是正文与版本，来源栏按需展开。输出先保存为草稿并关联项目 / 主题；只有用户确认已提交或交付时才形成对应工作进展，之后进入周报，避免“AI 写了一篇”循环变成未经确认的成果。已有草稿不作为自己下一次生成的事实依据；用户明确选择已确认产出时才可引用。

界面中的 AI 与外部 MCP 共用一套按范围搜索、读取片段、获取当前进展的服务；项目授权同时约束搜索与按 ID 读取。先贯通一个真实写作场景，再扩展格式和模板，不增加独立聊天资料库。

### 10.5 贯通示例与验收

“海外数据中心合作”项目关联“出海 / 数据中心”两个主题。周二会议形成“技术方案待确认”，周三记录“已协调技术团队，周五反馈”，周四关联提交的方案版本并记录“已提交，等待意见”。同一周另有不属于项目的日常审批协调。

- 在项目中看到方案现状、等待对象、会议和资料；两个主题视图均引用这份项目内容。
- 个人周报汇总当周推进和日常协调，方案提交只列一次，“等待意见”不写成验收完成。
- 写出海汇报时自动带入相关项目最新已确认进展和选择的资料，显示截至日期与引用；AI 草稿保存回项目。
- 草稿完成后再新增一条进展，只提醒可合入；已编辑的汇报和已定稿周报不被静默覆盖。
- 重启、归档、改主题或解除关联后原始资料仍在；迁移与备份覆盖新增关系，旧会议和无项目记录继续可用。

实现继续使用现有 SQLite：增加主题表、多对多项目主题关联和周报主题快照，不重建资料库。迁移重复执行不改变旧资料，旧备份恢复时主题为空；查询配套主题范围及去重，每项能力同时覆盖界面、检索、周报、AI 读取及备份恢复。代码与场景回归见 [项目主题](../apps/desktop/src/zhiji/components/projects/ProjectThemes.tsx)、[跨主题回归](../tests/project-themes.spec.mjs) 与 [原生测试](../apps/desktop/src-tauri/src/storage_tests.rs)。
