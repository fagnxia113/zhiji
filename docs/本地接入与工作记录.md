# 工作记录与本地接入

知记工作台可以记录会议之外的交付、沟通、决策、风险和参考笔记。记录时选择实际发生日期、状态和项目；这些资料会和会议及待办一起进入周报。项目关联使用资料的稳定标识，解除关联或归档项目不会删除原资料。会议关联项目后，其行动项默认沿用该项目；待办可单独指定。

周报从所选日期起连续汇总七天。周报窗口先展示将要使用的材料与缺口提示；「整理草稿」在本机组合资料，「AI 生成周报」会把材料发送至用户配置的模型服务。每次生成都保存为独立版本，可编辑、复制或导出包含来源快照的 Markdown。旧版已完成待办若没有完成时间，不会被猜测为本周成果；下次更新状态后会记录实际完成时间。

## 在本机连接 AI

进入「设置 → 本地 API / MCP」，选择端口和资料范围，然后开启接入。服务仅监听 `127.0.0.1`，仅在知记运行时可用。默认只能查询；需要让 AI 新增工作记录时，另行勾选「允许新增工作记录」。每次开启服务都会生成新令牌，停止后旧配置失效。界面显示最近操作与结果，但不记录正文或令牌。

点击「复制 MCP 配置」，将 JSON 粘贴到支持 `stdio` MCP 的本机 AI 客户端配置里。配置中有知记可执行文件路径、`--mcp` 参数、当前本地服务地址及令牌。不同客户端对配置外层字段的要求可能不同，需参照其说明调整。MCP 桥接进程不自行打开资料库，它通过已启动知记的本地 API 查询。纯云端客户端不能直接访问电脑的 `localhost`。

当前 MCP 工具：`list_projects`、`search_work`、`get_project_context`、`list_followups`、`report_material`；开启写入后增加 `capture_work`。`report_material` 返回七天资料和来源标识，AI 可据此编写周报，不会直接调用知记配置的模型。

## 直接调用 API

端点为 `POST http://127.0.0.1:17643/v1/workbench/{工具名}`，端口以设置页实际显示的地址为准。请求体是 JSON 对象，`Content-Type` 为 `application/json`，`Authorization` 为 `Bearer <配置中的 ZHIJI_API_TOKEN>`。成功时返回 `{ "data": ... }`，失败时返回 `{ "error": ... }`。例如检索：

```http
POST /v1/workbench/search_work HTTP/1.1
Host: 127.0.0.1:17643
Authorization: Bearer <令牌>
Content-Type: application/json

{"query":"报价"}
```

开启写入后，自动化工具可以记录已经发生的工作：

```json
{
  "id": "my-tool-20260927-001",
  "content": "已将报价发送客户，等待确认",
  "occurredOn": "2026-09-27",
  "projectId": "可选的项目 ID",
  "kind": "progress",
  "status": "waiting",
  "sourceLabel": "报价自动化"
}
```

`id` 由调用方生成，同一次工作重试须复用同一 `id`，相同内容不会重复写入；同一 `id` 对应不同内容会报错。`projectId` 不需要时请省略。项目受设置页选定的资料范围约束，调用者不能覆盖这个范围。工作记录应写实际进展，计划不要标记为完成。

本地 API 禁止浏览器跨站 `Origin` 请求，限制请求大小，并要求访问令牌。MCP 客户端拿到资料后可能会再发送给它使用的模型服务，具体由该客户端决定。令牌属于本机权限凭据，请勿上传或分享。

本项目的原生编译、测试和安装包以 GitHub Actions 的 Windows 工作流为准。
