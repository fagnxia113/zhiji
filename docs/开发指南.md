# 开发指南

最后核对：2026-09-28。以下命令均在知记仓库根目录执行，即本地工作区中的 `anarlog/`，不是它的父目录。父目录另有历史仓库，执行 Git 命令前先用 `git rev-parse --show-toplevel` 核对位置。

## 环境与启动

- Node.js 22 或更高；pnpm 版本以根目录 `package.json` 的 `packageManager` 为准，当前为 11.1.1。
- 前端预览只需要 Node.js / pnpm；真实桌面开发还需要 Rust、MSVC 和 Windows 构建环境。
- 没有本地 Rust 环境时，可运行前端检查；原生编译、数据测试与候选安装包由 Windows CI 验证。

```bash
pnpm install --frozen-lockfile
pnpm --filter @zhiji/desktop dev
```

开发服务默认端口 1422。浏览器预览没有真实 Tauri IPC，不能据此判断录音或数据库可用；界面回归通过测试专用内存 IPC 验证交互。

启动完整桌面程序：

```bash
pnpm --filter @zhiji/desktop tauri dev
```

## 验证命令

```bash
pnpm docs:check
pnpm --filter @zhiji/desktop typecheck
pnpm --filter @zhiji/desktop build
pnpm exec playwright install chromium
```

PowerShell 下运行界面回归：

```powershell
$env:BROWSER_CHANNEL = 'chromium'
node tests/run-ui.mjs
```

测试默认使用本机 Chrome；上述环境变量选择 Playwright Chromium。测试入口自动启动和关闭 Vite；运行前确保 1422 端口可用。截图保存在 `.tmp/ui-verification/`。当前测试清单以 [run-ui.mjs](../tests/run-ui.mjs) 为准。

具备原生构建环境时运行：

```bash
cargo check --locked --manifest-path apps/desktop/src-tauri/Cargo.toml
cargo test --locked --release --lib --manifest-path apps/desktop/src-tauri/Cargo.toml
python -m py_compile apps/desktop/src-tauri/src/speaker_engine.py
python scripts/test-speaker-engine.py
python scripts/test-speaker-clustering.py
```

Rust 与 Python 检查不能由 TypeScript 检查替代。CI 的具体顺序及产物以 [Desktop CI](../.github/workflows/build-desktop.yml) 为准。

录音仅采集、分段保存音频及会议笔记；模型未配置时仍可开始录音。结束时先排空音频写入并保存笔记，再提交新录音，随后按配置执行会后转写及本地角色区分。已移除实时字幕、流式音频队列、后台模型预热和实时模型安装依赖；已有实时初稿按旧状态继续显示，用户可重新生成完整原文。会后引擎只需要 SeacoParaformer、FSMN-VAD、标点和 CAMPPlus 四类模型，复用已有完整权重，不清理用户旧模型目录。

`tests/recording-after-meeting.spec.mjs` 使用浏览器模拟麦克风和真实 MediaRecorder 验证录音中不调用识别、无模型也能保存、最后笔记先于停录提交、新音频路径经过自动保存仍保留，以及会后才运行转写与角色区分。内存 IPC 不替代真实原生设备采集验收。

声音角色修正：现场麦克风并不代表“我”，单一聚类显示为匿名发言人并提示核对。在“原文校对”中可重新区分角色，选择实际发言人数或自动判断；此操作仅用原有时间戳提取声纹，不运行语音识别或 AI 纪要。正文、时间戳、纪要、决策、笔记和待办保留；角色编号变化后清除旧改名，需重新核对名称。人数提示只控制候选聚类数，不保证每个候选对应真实的人。

重新区分时的声纹特征保存在会议引擎的 `voiceprints/` 下，不进入录音目录、不包含正文；最多八份，30 分钟后不复用并在下次写入时清理。缓存按引擎版本、音源路径/长度/修改时间和分段时间戳区分，更改人数可复用；缓存损坏或无法写入不影响已有记录。写回使用原记录快照核对，失败、取消或处理期间的并发修改均不覆盖已有结果。真实聚类测试需在已安装 NumPy、Torch、FunASR 等依赖的本地会议 Python 中运行，不下载模型；普通 CI 环境会明确跳过这部分测试，仍执行 CLI 路径、UI 及原生数据保存回归。

录音与纪要性能回归：双轨共享识别模型，线上麦克风跳过声纹分析，现场会议保留多人聚类；Python 测试验证文本、时间戳及单轨失败恢复。原生测试验证纪要最多两段并行且按原文顺序返回、失败片段重试缓存，以及录音目录迁移和临时文件清理。真实 FFmpeg 文件测试需先准备 `resources/ffmpeg/ffmpeg.exe`，Windows CI 会自动准备。

录音目录顶层只存放用于回放的主录音，双轨源文件放在 `recordings/tracks/`。升级时仅整理已保存会议对应的旧源轨，不覆盖已有目标文件，迁移中断仍可读取旧位置。电脑声音只有零值或一个 PCM 量化单位的噪声时，新录音只保留麦克风主文件；不会用普通静音阈值删除低音量声音。

长会议分段生成采用最多两个并发请求，决策、行动项与引用仍按原文顺序汇总。未完成任务的成功片段在内存中保留 30 分钟（最多 64 段），重试使用相同模型、凭据、上下文和模板时复用，整场成功后清除。单次 AI 请求最多三次尝试，总预算六分钟，已超时的请求不自动重做。

## 修改边界

变更依赖时同步更新 `pnpm-lock.yaml`，常规 CI 保持 `--frozen-lockfile`；Rust 使用已提交的 `Cargo.lock` 和 `--locked`。不要为通过构建而默认关闭锁文件检查。

新增或修改资料表时，同步覆盖迁移、搜索、导出、备份和恢复。测试使用独立临时数据；数据库备份不包含录音，迁移整套资料时须保留录音目录。发布流程见 [发布手册](../RELEASE.md)。
