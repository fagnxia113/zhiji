# 知记个人工作台 · 产品验收记录

定位：面向独立推进工作的个人用户，连接会议资料、行动待办和每周回顾。正式交付需要可安装、可恢复、可解释的完整体验。

## 本次已实现

- 可读的侧栏导航，桌面与窄窗口布局，浅色与深色主题。
- 工作台概览：本周会议、已整理纪要、待办、周报入口与配置状态。
- 今日行动按逾期、今天到期和待完成直接进入筛选。
- 会议全文搜索、整理状态筛选、日期与修改时间排序、清除筛选。
- 待办按日期排序、负责人搜索和编辑；添加及编辑成功后才清空输入，处理中防止重复提交。
- 启动失败显示持久错误与重试；部分配置读取失败时保留资料库访问。
- 自动保存按顺序写入；弹窗 Tab 循环、Esc 与焦点恢复；中文输入法确认候选词不提交待办。
- 数据库恢复包含会议问答历史；恢复失败时事务回滚；旧备份缺少问答表或负责人列时兼容读取。
- 资料迁移先比较同名文件的实际内容，冲突时保留两份文件并提示处理；备份文件名增加唯一标识，避免快速连续备份冲突。
- 公众号摘要、正文、简短推荐版与配图说明。
- 关闭窗口由原生后端收起到托盘，缺少托盘时最小化到任务栏；退出前等待文字与待办写入，录音和处理期间阻止退出。
- 个人工作台新增功能路线与逐项实施、验收标准，见《个人工作台功能规划》。

## 验证方式

正式构建统一通过 GitHub Actions 的 Desktop CI 完成，不要求在使用者电脑安装 Rust 或 Visual C++ 构建环境。

GitHub CI 执行前端构建、Playwright 界面回归、Rust 原生编译、真实 SQLite 与文件迁移测试、Python 引擎语法检查。界面截图作为 Actions artifact 保存。

非正式发布分支还会生成候选 NSIS 安装包，在 GitHub Windows runner 的临时目录静默安装，启动已安装的真实程序，识别工作台窗口后验证关闭请求隐藏窗口且保留进程。候选包禁用更新签名产物生成，只上传 Actions artifact，不修改 Releases 或自动更新清单。窗口测试输出启动日志，失败时也保留已生成的安装包供诊断；产物存在不代表测试通过。

原生数据测试覆盖所有工作资料表的备份恢复、恢复中途写入失败的事务回滚、旧备份兼容、损坏备份不改动现有资料、路径越界拒绝、重复数据迁移、同名不同内容文件冲突保护和相同文件断点续迁。测试使用独立临时数据库和文件，不访问用户资料目录。

界面测试入口：`node tests/run-ui.mjs`（自动启动并关闭测试服务）。GitHub 配置 `BROWSER_CHANNEL=chromium`，Playwright 使用锁定开发依赖。界面测试注入仅存在于 tests 目录的内存 IPC，验证 React 交互，不接触真实资料。

界面测试覆盖工作台跳转、待办失败保留与重试、负责人修改、会议筛选、弹窗键盘焦点、400px 宽度、启动失败恢复、部分配置失败、空数据；截图在 `.tmp/ui-verification/`。

## 正式发布仍需证据

- 当前提交对应的 GitHub 原生编译与关闭窗口实测结果。
- Windows 安装包打包、全新安装与升级保留数据验证。
- 使用真实麦克风与系统声音完成录音、保存、回放、转写；真实 AI 服务完成纪要、问答与周报。
- 数据库备份恢复及录音目录迁移验证。现有 SQLite 备份不包含录音二进制文件。
- 发布所用语音模型、FFmpeg 和依赖的分发许可及通知文件检查。
- 安装包的 Windows 代码签名与自动更新签名分别核验；当前配置未提供 Windows 签名证书。

浏览器测试不能证明原生录音、数据库、语音模型或 AI 服务已经通过验收。只有这些检查的实际结果齐备，才能宣称本次优化版已经达到可正式销售交付的状态。
