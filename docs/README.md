## 文档维护规则

- 同一主题更新原文档，不新增“最终版”“优化版”等平行入口。
- 操作说明与阶段记录分开：现行文档说明现在怎么做；旧提案、版本复盘放入 `archive/日期/`，并加历史标记。目录日期是归档日期，不是原文发布日期。
- 规划必须区分已实现、部分实现、待开发，并链接实际入口；不能只凭文件存在判断功能已经接入。
- 验收结论写明提交、平台、命令和结果。历史截图、旧测试通过记录不能代替当前提交的验证。
- 修改文件位置时，同步更新引用；执行 `pnpm docs:check` 检查现行 Markdown 的本地文件链接。检查不访问网络，也不验证标题锚点或功能是否正确。
- 临时探针、截图、日志放在已忽略的 `.tmp/`。历史原文中的旧链接不纳入检查；归档导航必须可用。
- 发布手册记录稳定流程；每版发布说明随具体版本维护。宣传文案不能代替功能或验收说明。
